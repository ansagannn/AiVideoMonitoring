# AI Camera Safety — MVP

Переработанный исходный проект: Python + YOLOv8 + OpenCV + FastAPI + SQLite,
React / TypeScript. Полный интерфейс на русском и казахском, переключатель RU / ҚАЗ,
сохранение выбранного языка, адаптивный dashboard для телефона.

## Быстрый запуск Windows

Нужны Python 3.12 и Node.js 20+. Откройте терминал в распакованном проекте.

```powershell
cd frontend
npm ci
npm run build
cd ../backend
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://localhost:8000. Для локальной демонстрации:
`admin / admin123`, `manager / manager123`, `operator / operator123`.
Администратор и руководитель настраивают камеры и правила, оператор проверяет события.
Пароли можно задать через `AI_MONITOR_PASSWORD_ADMIN`, `AI_MONITOR_PASSWORD_MANAGER`,
`AI_MONITOR_PASSWORD_OPERATOR` до запуска сервера.

## YOLO: реальная аналитика

В исходном архиве нет весов нейросети. Поместите `yolov8n.pt` в `backend/models/`
или задайте `AI_MONITOR_YOLO_MODEL` — полный путь к совместимым весам Ultralytics YOLO.
Для разрешения загрузки весов из интернета перед запуском:

```powershell
$env:AI_MONITOR_YOLO_AUTO_DOWNLOAD="1"
```

Без весов сервер и интерфейс работают, но показывают недоступность анализа.
Синтетические камеры явно обозначены как демонстрация. Автоматические события
по ним не генерируются; тестовые сценарии запускаются в настройках.
После установки модели перезапустите сервер.

## Docker

```bash
cp .env.example .env
# при необходимости отредактируйте .env
# положите веса в backend/models/yolov8n.pt
docker compose up --build
```

http://localhost:8000. Данные и снимки сохраняются в томе `safety-data`.
Путь к локальному видео внутри контейнера: `/videos/имя.mp4`, файл положите в
`backend/videos/`. Docker начинает с отдельной базы. Для переноса исходной истории
укажите вместо `safety-data:/data` привязку `./backend:/data` в compose.

## Камеры и зоны

В разделе «Камеры» нажмите «Подключить камеру». Доступны RTSP, MJPEG, JPEG,
локальное видео и синтетические сцены. Существующий источник можно изменить,
включить или выключить. RTSP-соединение и чтение видео сохраняются между кадрами;
видеофайл последовательно проигрывается и повторяется в конце.

Для запрещённой зоны выберите тип «Опасная / запрещённая зона» и задайте полигон
в координатах от 0 до 1 относительно ширины и высоты кадра, например:
`[[0.1,0.1],[0.9,0.1],[0.9,0.9],[0.1,0.9]]`.
При подключении камеры задаётся первая зона; дополнительные существующие зоны
сохраняются. Несколько зон можно настроить через `POST /api/camera-sources`
(API-документация: `/docs`, требуется Bearer-токен из `/api/auth/login`).
Для этого MVP используется центр рамки человека. Контур зоны нужно выбирать
с учётом перспективы и реального положения камеры.

## Что определяет MVP

| Категория | Условие |
|---|---|
| Нормальная активность | Успешный анализ, без срабатывания правил риска; отображается на камере |
| Подозрительная активность | Нахождение в зоне полки / склада дольше установленного порога |
| Возможная драка / нападение | Два близких человека с устойчивыми резкими перемещениями рамок |
| Возможное падение | Вертикальная рамка меняется на горизонтальную и сохраняет положение |
| Опасная ситуация | Человек в настроенной запрещённой зоне |

Это эвристический MVP поверх YOLO-детектора людей, без обученной модели распознавания
действий. Не подтверждает факт кражи, нападения или падения. Бег, наклоны, перекрытия
людей и движение камеры могут вызывать ошибки. Падение без видимого предшествующего
вертикального положения может быть пропущено; смена трека и редкие кадры также снижают
качество. Каски, жилеты, огонь и дым не распознаются отдельной моделью в этой версии.
Для повышения точности нужен пилот с размеченными записями, настройка зон и порогов,
а затем pose/action-модель и замеры качества на отдельной тестовой выборке.
Официальная документация: https://docs.ultralytics.com/tasks/detect/ и
https://docs.ultralytics.com/tasks/pose/.

## События и Alert

Камера → YOLO → трекинг → временные правила → событие → dashboard / Telegram → оператор.
Событие содержит время, камеру, категорию, неизменяемый JPEG-кадр на момент фиксации,
метку режима (демо / эвристика / архив), статус и отзыв оператора.
Короткое видео не записывается: выполнен вариант «кадр» из ТЗ.
Кадры хранятся в базе, поэтому не исчезают после перезапуска и не подменяются
текущим изображением камеры. Если свежего кадра нет, интерфейс сообщает об этом.
Старые события сохранены; их исходные SVG-превью являются архивными иллюстрациями.

«Подтвердить» и «Ложная тревога» сохраняют решение, комментарий, время и фактический
логин пользователя. На dashboard доступны фильтры по камере, категории, статусу и датам,
а также аналитика по сохранённым событиям. Нормальные действия не создают
постоянного потока уведомлений. Повторные автоматические сигналы одинакового типа,
камеры и зоны ограничены интервалом 5 минут.

### Telegram ответственному сотруднику

До запуска сервера задайте:

```powershell
$env:TELEGRAM_BOT_TOKEN="токен вашего бота"
$env:TELEGRAM_CHAT_ID="ID чата ответственного сотрудника"
$env:TELEGRAM_WEBHOOK_SECRET="случайная секретная строка"
```

Ответственный сотрудник должен начать диалог с ботом либо добавить бота в нужную группу.
Риск-события отправляются автоматически; при ошибке повторяются не ранее чем через
60 секунд. Доставленные события помечаются `telegram_sent`. Без настройки Telegram
работают dashboard и внутренние уведомления. Тестовые сценарии могут отправить
уведомление в настроенный чат с явной меткой ДЕМО.

Для кнопок Telegram нужен публичный HTTPS-адрес сервера: зарегистрируйте webhook
через Telegram `setWebhook`, URL `https://ваш-сервер/api/telegram/callback`,
`secret_token` должен совпадать с `TELEGRAM_WEBHOOK_SECRET`. Callback без секрета
отклоняется. Для локального запуска подтверждение работает в dashboard.
Сбой после отправки сообщения, но до записи результата в БД может привести к
повторной доставке; в MVP доставка имеет семантику at-least-once.

## Разработка и проверки

```bash
cd frontend
npm ci
npm run lint
npm run build
npm run dev
```

Vite проксирует `/api` на `http://localhost:8000`. `VITE_API_URL` оставлен пустым;
для отдельного адреса API задайте его вручную. Для Linux/macOS backend:

```bash
cd backend
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests -q
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Тесты проверяют падение и подавление повторов, движение при возможной драке,
запрещённый полигон, длительное пребывание, трекинг, перезапуск настроек,
сохранение кадра, права доступа, доставку уведомлений и последовательное чтение видео.
Фактическая точность на реальных камерах и доставка в реальный Telegram-чат
не проверены: веса и доступ к камерам/боту не предоставлены.
SQLite и сервер с одним процессом подходят для MVP. Увеличение числа камер требует
раздельных capture/inference workers; сейчас камеры анализируются последовательно,
поэтому `fps_limit` задаёт верхний предел, а фактическая частота зависит от нагрузки.
Токены авторизации хранятся в памяти; после перезапуска нужно войти заново.
Исходная история находится в `backend/monitoring.db` и сохранена при обновлении.

## Проверка перед пилотом

У каждой камеры кнопка «Проверить AI» отдельно проверяет свежесть кадра и загрузку модели.
`GET /api/ai/status` и `GET /api/camera-sources/{id}/readiness` доступны с авторизацией.
Синтетическая камера никогда не получает статус готового реального AI-потока.
Для камеры ТРЦ/склада нужен предоставленный владельцем прямой RTSP/MJPEG/JPEG
поток либо видеозапись. Страница стороннего сайта и YouTube-плеер не являются
прямым источником для OpenCV. Пароли камер задавайте локально, не публикуйте их
в ссылках браузерного демо. До приёмки нужно проверить каждый тип события на
записях объекта, измерить ложные тревоги и пропуски; текущие падения и драки
остаются эвристиками. Размещённое browser live-demo пока не связано с Python-сервером.

JPEG-камеры подходят для просмотра и обнаружения людей, анализ действий и тревоги по движениям на них отключены из-за редких кадров.

Прямые запросы из среды разработки завершились сетевым тайм-аутом, декодирование HLS на реальной сети пока не подтверждено. Это не камеры внутри ТРЦ или склада. Недоступный источник показывает «Нет связи», синтетическая подмена не используется.


### Публикация на Netlify

Netlify размещает React-интерфейс. FastAPI, OpenCV, YOLO, фоновые подключения камер и SQLite запускаются отдельным постоянным Docker-сервисом на сервере с HTTPS. `docker-compose.yml` сохраняет базу в томе и подключает папку моделей. Сервер должен разрешать сетевые запросы к публичным камерам.

1. Разверните Docker-сервис на своём сервере, установите веса YOLO и задайте собственные пароли через переменные `AI_MONITOR_PASSWORD_*`. Настройте HTTPS и проверьте `/healthz`, вход и получение кадров.
2. Создайте отдельный проект Netlify для AiVideoMonitoring. Подключите репозиторий с `netlify.toml` в корне AiVideoMonitoring.
3. В переменных окружения Netlify для сборки задайте `VITE_API_URL` равным HTTPS-адресу FastAPI, например `https://api.your-domain.example`, без `/api` в конце. Это публичный адрес; секреты и пароли в него не помещаются.
4. Опубликуйте сайт. Конфигурация выбирает frontend как базовую папку, собирает интерфейс и публикует dist с поддержкой маршрутов SPA. При отсутствии адреса API сборка останавливается с пояснением.
5. После публикации проверьте вход, раздел камер и кнопку «Проверить AI», затем создание и подтверждение тестового события. При изменении адреса API нужна новая сборка.

Ручная загрузка имеющейся папки dist без настроенного VITE_API_URL не подключает Python-сервер. Встроенный статический демо-сайт также не запускает YOLO.


### Сервер Render без собственного VPS

`render.yaml` содержит подготовленную конфигурацию платного Docker Web Service: 1 CPU / 2 GB RAM, один процесс приложения и постоянный диск 1 GB для SQLite и модели. Это отправная конфигурация для демо, производительность нескольких камер необходимо измерить после запуска. Применение Blueprint создаёт платные ресурсы; сначала проверьте и подтвердите стоимость в Render. Бесплатный сервис засыпает без входящего трафика и не сохраняет SQLite после перезапуска, поэтому для постоянного мониторинга эта конфигурация использует платный тариф.

Подключите Render и репозиторий с проектом, выберите Blueprint из `render.yaml`, задайте три собственных пароля. После запуска проверьте `/healthz`, наличие модели через `/api/ai/status` после входа и получение кадров публичных камер. Автозагрузка YOLO включена, но её успех необходимо проверить на сервере. Передайте полученный HTTPS-адрес сервера в переменную `VITE_API_URL` проекта Netlify и пересоберите интерфейс.

Docker-сервис также отдаёт встроенный интерфейс по своему адресу, поэтому его можно проверить до подключения Netlify. После перезапуска потребуется повторный вход: сессии хранятся в памяти процесса. Историческая база из архива не переносится автоматически в новый диск — создаётся чистая база со стандартными источниками.
